# 需求基线

- 基线版本：1.0
- 基线日期：2026-08-09
- 产品：IC-84 Raster Console
- 状态：已建立，后续变更需记录原因

## 产品目标

IC-84 将用户输入的图片或视频转换为字符、点阵或半调构成的低分辨率复古终端画面，并提供实时参数调整、结果预览和媒体保存。产品视觉应像一台真实存在的 80 年代桌面视觉终端，而不是普通网页卡片界面。

## 功能需求

| 编号 | 需求 |
| --- | --- |
| REQ-CORE-001 | 用户可以载入图片，并在当前终端参数下看到处理结果。 |
| REQ-CORE-002 | 用户可以载入视频，并看到连续动态的处理结果。 |
| REQ-CORE-003 | 支持字符（ASCII）、点阵（Dots）和半调（Halftone）三种渲染方式。 |
| REQ-CORE-004 | 字符模式支持 DENSE、BLOCK、LINE 三种字符集，三者应产生可辨认的视觉差异。 |
| REQ-CORE-005 | 支持列数、缩放和对比度参数。 |
| REQ-CORE-006 | 支持反相、抖动和辉光开关。 |
| REQ-CORE-007 | 支持绿屏、琥珀和冷白三种屏幕色调。 |
| REQ-CORE-008 | 参数变化应及时反映在当前图片或视频预览中。 |
| REQ-IMG-001 | 图片处理和导出必须保持输入图片的显示宽高比，不得横向或纵向压缩。 |
| REQ-IMG-002 | 用户可以保存当前参数生成的完整图片，而不是界面截图或被裁掉的局部画面。 |
| REQ-VID-001 | 视频必须逐帧转换为所选栅格单元，不能只叠加色彩滤镜。 |
| REQ-VID-002 | 视频处理结果必须包含连续动态画面；保存时输出完整视频，不能保存为单帧图片。 |
| REQ-VID-003 | 视频处理、预览和导出必须保持输入视频的显示宽高比。 |
| REQ-VID-004 | 视频栅格画面的背景应与图片输出一样使用黑色基底，不额外加入绿色底光。 |
| REQ-VID-005 | 在输入包含音轨且运行环境支持时，处理后视频应保留音频。 |
| REQ-WEB-001 | Web 端提供完整的图片、视频、参数调整、预览和保存能力。 |
| REQ-WEB-002 | Web 端开屏演示图应保持既定笑脸/摇椅构图和自然比例。 |
| REQ-WEB-003 | Web 视频保存优先使用 WebCodecs 离线逐帧解码、独立高清 Canvas 重绘和重新编码，不得依赖视频按正常速度播放。 |
| REQ-WEB-004 | Web 视频导出优先输出 MP4/H.264；不支持时降级为 WebM/VP9，编码配置必须先通过 `VideoEncoder.isConfigSupported()` 检查。 |
| REQ-WEB-005 | Web 导出提供快速、高清、精细三个画质档，分别限制在 1280x720、1920x1080、2560x1440 边界内；始终保持输入比例、输出偶数尺寸且默认不放大低分辨率输入。 |
| REQ-WEB-006 | Web 导出提供跟随源视频、24、30、60 FPS；降低帧率时按时间戳均匀抽帧且不改变时长，高于源帧率的选项应禁用或提示。 |
| REQ-WEB-007 | Web 导出设置面板应显示预计尺寸、帧率、编码格式和文件大小；导出时显示百分比、当前帧数并允许取消。 |
| REQ-WEB-008 | Web 离线导出应优先在 Worker 与 OffscreenCanvas 中运行；不支持 WebCodecs 时允许明确提示后使用 MediaRecorder 兼容路径。 |
| REQ-WEB-009 | Web 视频应优先直接复用兼容音轨，其次使用浏览器音频编解码转为 AAC/Opus；均不支持时允许无声导出，但必须明确提示。 |
| REQ-WEB-010 | Web 电视底部提供“屏幕反光”开关，默认开启；关闭时仅隐藏 CRT 玻璃反光层，不改变实时栅格渲染及图片、视频导出内容。 |
| REQ-MP-001 | 小程序采用适合手机的纵向电视布局：屏幕为视觉中心，主要控制不溢出、不遮挡。 |
| REQ-MP-002 | 小程序提供插入图片、插入视频和保存当前输出操作。 |
| REQ-MP-003 | 小程序处理后的视频必须直接在页面内播放，并可保存到相册。 |
| REQ-MP-004 | 小程序开屏演示可以使用独立内部适配比例，但界面显示的初始缩放仍为 `1.00`。 |
| REQ-XPLAT-001 | 微信开发者工具和真实手机在主体形状、明暗结构和渲染模式上应保持一致。 |
| REQ-XPLAT-002 | 字符、小点和半调单元在真实手机的小字号 Canvas 上必须保持可见，不因 CRT 叠层完全消失。 |

## 视觉需求

| 编号 | 需求 |
| --- | --- |
| REQ-UI-001 | 外壳使用白色/浅灰色拟物硬件语言，包含螺丝、内阴影、细颗粒、面板分区和实体按键层次。 |
| REQ-UI-002 | CRT 屏幕包含圆角玻璃、扫描线、暗角、低分辨率质感和受控辉光。 |
| REQ-UI-003 | 风格介于现代工业产品和 80 年代终端设备之间，保持干净、克制和机械感。 |
| REQ-UI-004 | 按钮具有明确按压状态，文字完整可读；控件不得超出容器或互相遮挡。 |
| REQ-UI-005 | 使用等宽字体表达终端信息，中文操作文字在目标设备上保持可读。 |

## 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-PERF-001 | 图片参数调整应接近实时，不出现明显长时间阻塞。 |
| NFR-PERF-002 | 视频处理可异步等待，但必须提供明确的处理中、成功和失败状态。 |
| NFR-PERF-003 | Web 离线导出速度由设备性能决定，不得人为按媒体播放时钟等待；性能验收以“与播放时长解耦”为准，不承诺所有设备都快于实时。 |
| NFR-COMPAT-001 | Web 优先支持当前版本 Chromium 浏览器；小程序优先支持微信开发者工具和主流 Android/iOS 微信环境。 |
| NFR-MAINT-001 | 跨端参数名称和语义保持稳定，变化必须更新契约。 |
| NFR-MAINT-002 | 机器相关路径、服务地址和发布域名不得继续分散到多个业务逻辑位置。 |
| NFR-DATA-001 | 用户媒体仅用于当前处理；生成文件、上传文件和临时文件不得提交到版本库。 |

## 范围边界

当前范围包含单个图片或单个视频的处理、预览和保存。不包含账户系统、云端作品库、批量队列、社交分享、付费功能和长期媒体托管。

## 基线变更流程

1. 新需求分配稳定编号，避免复用已有编号。
2. 在本文件记录需求，在 `spec.md` 中补充行为，并在 `acceptance-criteria.md` 中定义验证方式。
3. 在 `requirements-audit.md` 标记当前覆盖状态，在 `tasks.md` 创建实施任务。
4. 删除或改变已有需求时，在 `CHANGELOG.md` 说明影响；涉及关键技术方向时新增 ADR。
