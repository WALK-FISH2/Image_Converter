# 需求审计

- 审计日期：2026-08-09
- 审计方式：代码静态核对、浏览器实际媒体验证与既有真机反馈汇总
- 注意：标记“代码已覆盖”不等同于通过完整设备回归

## 状态定义

- `已覆盖`：代码路径存在，且已有明确验证反馈。
- `部分覆盖`：主要路径存在，但仍有端侧差异、未实现参数或缺少验证。
- `待验证`：从代码看具备能力，但尚无足够运行证据。
- `未覆盖`：当前实现中没有对应能力。

## 主要风险

| 风险 | 影响 | 建议任务 |
| --- | --- | --- |
| Web、小程序、Server 分别维护字符集、色调和亮度映射 | 修一端后另一端可能漂移 | TASK-RENDER-001 |
| 小程序 API 地址硬编码在页面脚本 | 模拟器与真机切换容易失败 | TASK-CONFIG-001 |
| Server 的 `glow` 参数当前没有作用 | UI 与成片结果不一致 | TASK-RENDER-002 |
| Web 使用内存缓冲封装完整输出 | 超长或高分辨率视频可能占用大量内存 | TASK-WEB-EXPORT-003 |
| Server 同步请求且没有进度接口 | 长视频期间只能显示笼统等待状态 | TASK-VIDEO-002 |
| 上传、临时和输出文件没有自动清理策略 | 长期运行会占满磁盘 | TASK-OPS-001 |
| 缺少自动化宽高比和跨端金样测试 | 已修复的“变窄”“单元消失”问题容易回归 | TASK-TEST-001 |
