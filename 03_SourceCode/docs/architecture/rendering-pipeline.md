# 渲染流程

## 共同模型

三端都遵循以下概念流程：

```text
输入媒体
  -> 按显示宽高比解码
  -> 等比缩放并居中采样
  -> 转换为亮度
  -> 对比度
  -> 有序抖动（可选）
  -> 反相（可选）
  -> 字符 / 点阵 / 半调几何单元
  -> 色调与局部辉光
  -> 扫描线、噪声、暗角等 CRT 表现
  -> 预览或导出
```

## 比例规则

### 输入比例

- 图片比例为解码后的 `width / height`。
- 视频比例为 `pixelWidth * sampleAspectRatio / pixelHeight`。
- 比例必须在进入低分辨率采样前确定。

### 采样

输入使用 contain 方式进入栅格范围：

1. 先按输入显示比例计算目标宽高。
2. 结合字符单元的 `cellH / cellW` 修正采样空间，避免等宽字符造成视觉压缩。
3. 等比缩放并居中。
4. 未覆盖区域填充黑色。

`scale` 只改变内容占据栅格范围的大小，不改变输入比例。禁止分别修改 X/Y 缩放来填满屏幕。

### 输出

- Web 图片继续从当前 Canvas 按输入比例导出；Web 视频必须在独立目标尺寸 Canvas 上从解码帧重新采样和渲染，不得截取页面 Canvas 后放大。
- Server 以 `max(OUTPUT_WIDTH, OUTPUT_HEIGHT)` 作为长边基准，按输入比例计算另一边，并调整为 H.264 所需偶数尺寸。
- 小程序用户视频直接使用 Server 输出尺寸。
- 小程序图片目前导出 CRT Canvas，比例行为仍列为验收项，修改时应复用与 Web/Server 相同的独立导出画布原则。

## 栅格尺寸

- 横向单元数由 `cols` 决定。
- 行数根据输出区域的 `height / width` 和字符视觉宽高补偿计算。
- 当前小程序和 Server 使用近似公式 `rows = round(cols * height / width * 0.52)`，最低 24 行。
- Web 使用相近但不完全相同的系数。更改系数会影响主体比例，必须使用圆形和人脸测试图回归。

## 亮度处理

共同亮度公式：

```text
luminance = 0.2126R + 0.7152G + 0.0722B
brightness = (luminance / 255 - 0.5) * contrast + 0.5
```

启用抖动时使用 4x4 Bayer 风格矩阵进行小幅亮度扰动；启用反相时执行 `1 - brightness`，最后限制到 `[0, 1]`。

小程序开屏演示有真机可见性补偿：非黑演示单元具有最低亮度/尺寸/透明度，并对字符、点阵、半调分别设置辉光。该补偿只用于 `sourceKind=demo`，不能改变用户上传媒体的灰阶结果。

## 三种模式

### 字符

亮度映射到从暗到亮排列的字符集。字符集前导空格数量是亮度阶梯的一部分，不得随意删除。

浏览器和小程序依赖 Canvas 字体渲染；Server 使用内置 5x7 字形和 BLOCK 程序绘制。增加字符时必须确认 Server 有对应字形或明确回退策略。

### 点阵

每个单元绘制圆形。亮度越高，半径和前景强度越大。真实手机的小点不能小于设备可稳定栅格化的阈值。

### 半调

每个单元绘制交错方向的短矩形/点形。亮度控制宽度或等效面积；低亮度单元同样需要真机最小可见尺寸。

## CRT 效果边界

- CRT 扫描线、暗角和噪声是视觉表现，不得改变主体几何比例。
- 辉光是前景单元周围的局部效果，不得把整幅背景染成色调颜色。
- 图片和视频输出的背景基准均为黑色。
- 各叠层透明度变化后必须测试暗部，防止低亮度字符、小点和半调单元消失。

## 开屏演示与用户媒体

开屏笑脸是程序生成的模拟信号，不是普通用户图片。它可以有独立的内部比例补偿和动画，但必须遵守：

- Web 保持既定横向构图。
- 小程序在竖屏中尽量放大并完整显示，主体形状接近 Web。
- 界面中的用户缩放值不因内部演示适配而改变。
- 一旦用户加载图片或视频，所有演示专用补偿必须退出。

## 修改检查表

- 是否同时检查了 Web、MiniProgram、Server？
- 是否用横图、竖图、方图和圆形测试图验证？
- 是否检查字符、点阵和半调三个模式？
- 是否在真实手机上检查了暗部和小单元？
- 是否验证保存文件，而不只看界面预览？
- 是否更新参数契约、需求审计和兼容性矩阵？

## Web 离线视频导出

```text
File/Blob
  -> 媒体库解封装并读取旋转、显示尺寸、时长、帧率和轨道
  -> WebCodecs VideoDecoder 离线输出 VideoFrame
  -> 按目标时间戳均匀选择帧
  -> Worker + OffscreenCanvas 以目标偶数尺寸重新执行栅格渲染
  -> VideoEncoder 能力检测（H.264 优先，VP9 降级）
  -> 音频包直通或 AudioDecoder/AudioEncoder 转码
  -> MP4/WebM 封装
  -> Blob 下载
```

导出尺寸按 contain 规则限制在 1280x720、1920x1080 或 2560x1440，且不放大源视频。编码使用可变码率并请求硬件优先，但浏览器可以回退软件实现。处理循环只受解码、渲染和编码吞吐限制，不等待真实媒体时钟。

取消操作必须通过 AbortSignal/Worker 消息停止输入迭代，关闭所有 VideoFrame 和编码资源；失败或取消不得下载半成品。
