# 实施计划

- 计划更新：2026-08-09
- 当前阶段：可运行原型稳定化

## 阶段 0：核心原型

状态：主要能力已完成。

目标：建立可操作的 Web 和小程序终端，支持图片/视频、三种渲染模式、参数调整和保存。

已有结果：

- Web 横向工业终端界面和浏览器 Canvas 渲染。
- 小程序纵向电视布局和真机可见性修复。
- Server FFmpeg 视频逐帧处理、比例保持、MP4 返回。
- 图片和视频保存入口。

剩余工作以回归验证和已知差异为主，不在本阶段继续扩大产品范围。

## 阶段 1：契约与一致性

目标：把“当前看起来一致”提升为“参数、比例和保存行为可以验证”。

完成条件：

- 建立文档体系和需求追踪。
- 建立稳定测试素材和比例自动检查。
- 完成 Web 端 Vite 迁移、WebCodecs 离线逐帧导出、独立高清 Canvas 和导出设置面板。
- 验证 MP4/H.264 优先、WebM/VP9 降级、音频保留、进度与取消。
- 明确并修复 Server `glow` 行为。
- 核对三端字符集、色调和模式差异。
- 完成 Android、iOS、开发者工具和 Chromium 基线验证。

关联任务：`TASK-DOC-001`、`TASK-TEST-001`、`TASK-RENDER-001/002`、`TASK-WEB-EXPORT-001/002/003`。

## 阶段 2：配置与视频工程化

目标：降低模拟器/真机切换成本，改善视频处理反馈和资源管理。

完成条件：

- 小程序 API 基址拥有明确的开发、局域网和生产配置入口。
- Server 对处理任务提供可观察状态或进度。
- 上传和输出文件有清理策略。
- 视频性能有分阶段指标，优化不牺牲逐帧栅格质量。
- Web 视频离线导出完成实际媒体性能与兼容性基线。

关联任务：`TASK-CONFIG-001`、`TASK-VIDEO-001/002`、`TASK-OPS-001`。

## 阶段 3：可发布服务

目标：满足真实用户通过小程序 HTTPS 服务处理媒体的基本上线条件。

完成条件：

- HTTPS 部署和微信合法域名配置。
- 文件类型校验、鉴权或使用额度、限流和超时策略。
- 日志、错误监控、磁盘与 CPU 告警。
- 隐私说明和媒体保留策略。
- 完整验收矩阵通过并形成发布记录。

该阶段开始前需要新的部署和数据治理决策，不应直接沿用无鉴权本地原型服务。

## 排序原则

1. P1 正确性问题优先于新增功能。
2. 先建立可验证标准，再重构三端共享逻辑。
3. 性能优化不得改变逐帧重建、黑色背景和比例保持要求。
4. 正式部署前必须先处理安全、清理和隐私问题。
