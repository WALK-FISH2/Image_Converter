# 测试策略

## 目标

测试优先保护最容易回归的四类行为：输入比例、完整视频输出、三种模式的真实栅格化、开发者工具与真机的一致性。

## 测试层级

### 1. 静态检查

每次修改 JavaScript 后执行相关命令：

```powershell
node --check Web\script.js
node --check MiniProgram\pages\index\index.js
node --check Server\server.js
node --check Server\smoke-test.js
```

同时检查 WXML、WXSS、HTML 和 CSS 是否存在未闭合结构、溢出和文字裁切。静态检查不能证明视觉正确。

### 2. Server 冒烟测试

`smoke-test.js` 会启动服务、等待 `/health`、上传一个视频并打印响应。默认测试文件为：

```text
Server/storage/test-input.mp4
```

也可以设置 `INPUT_VIDEO`。冒烟测试至少验证 HTTP 主路径，不代替对输出视频内容的检查。

### 3. 输出媒体检查

对生成图片和视频记录：

- 像素宽高和显示宽高比。
- 视频时长、帧率、编码格式、是否有音轨。
- 第一帧、中间帧和末帧是否均为所选栅格模式。
- 黑色背景和主体是否完整。
- 圆形测试标记是否仍接近圆形。

优先使用 FFprobe 读取媒体元数据，使用固定截图检查关键帧。

### 4. Web 手工回归

至少覆盖：

- 开屏演示。
- 横图、竖图、方图。
- 横向和竖向视频。
- 三种渲染模式和三种字符集。
- 三种色调与三个开关。
- PNG、MP4/H.264 和 WebM/VP9 保存文件。
- 10 秒测试视频离线导出不依赖正常播放计时，并记录总耗时、处理帧数和编码选择。
- 快速、高清、精细三个画质档的尺寸、偶数宽高、不放大和比例。
- 源帧率、24、30、60 FPS 的禁用规则、时长和实际帧率。
- 音频直通、音频转码和无声告警路径。
- 导出取消、重复提交阻止、视频播放位置和播放状态恢复。
- 1366x768、1920x1080 视口。

### 5. 小程序设备回归

微信开发者工具仅用于快速检查逻辑和布局。以下改动必须使用真机：

- 字符集、字体、字号、透明度和辉光。
- 点阵半径、半调尺寸、扫描线和暗角。
- Canvas DPR 或画布尺寸。
- 视频上传、下载、播放和保存相册。
- 局域网 API 或合法域名配置。

最低设备矩阵为开发者工具、Android 真机、iOS 真机。当前缺失项见 `compatibility-matrix.md`。

## 回归素材

项目测试素材统一放在 `tests/fixtures`，不得引用源码项目以外的个人记录目录。测试输入应可复现、体积受控并使用稳定名称：

- `still-landscape.png`
- `motion-landscape-10s.mp4`
- `motion-portrait-3s.mp4`

后续素材命名：

- `aspect-square-1x1.*`
- `tones-dark-mid-light.*`
- `motion-silent.mp4`
- `motion-24fps.mp4`
- `motion-2997fps.mp4`
- `motion-5994fps.mp4`

## 金样策略

后续为每个运行端建立少量金样，不追求噪声层逐像素一致：

- 几何金样：宽高比、主体包围盒、圆形偏差。
- 结构金样：非黑单元分布和亮度直方图。
- 模式金样：字符、圆点、半调单元的形态识别。
- 视频金样：抽取固定时间点比较，并验证时长和音频。

随机噪声和设备字体差异应通过容差或关闭随机层处理，不能让测试永久不稳定。

## 缺陷分级

- P0：保存文件损坏、媒体丢失、服务导致机器资源不可恢复问题。
- P1：视频变静态、比例明显变形、主体大片缺失、无法保存或真机完全不可用。
- P2：某模式/字符集错误、音频缺失、局域网配置失败、明显 UI 重叠。
- P3：轻微色差、颗粒强度、装饰细节或非阻塞文案问题。

## 完成证据

每个完成任务至少记录验证命令或设备、测试素材、结果和日期。只有“看代码应该可以”时，任务状态保持待验证。
